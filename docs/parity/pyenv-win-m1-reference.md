### How the pyenv-win test suite observes output

Keep these rules in mind when reading `[test]` literals:

- **Output normalization.** `do_run` decodes stdout as UTF-8 and keeps only the text after the last form feed `\x0c`,
  which a `cls` in the cmd AutoRun can produce. It then strips leading and trailing `\r`/`\n`. stderr is `.strip()`ped
  [src tests\test_pyenv_helpers.py:120-126]. Test literals therefore never show a trailing newline or trailing empty
  lines.
- **Exit codes.** Tests never assert an exit code, except `returncode == 1` in
  `tests\test_pyenv_feature_exec.py:147-150`.
- **Invocation.** Commands run as `cmd /d /c call <tmp>\pyenv dir with spaces\bin\pyenv.bat …`
  [src tests\conftest.py:36-60, 95-98]. The cwd is `<tmp>\local dir with spaces` [src tests\conftest.py:30-32, 89-90].
  An empty `<tmp>\.python-version` is created in the parent of the cwd [src tests\conftest.py:83], which stops the
  upward search for `.python-version` (see *Version selection*).
- **Architectures.** Every test runs twice, with `PYENV_FORCE_ARCH=AMD64` and with `X86` [src tests\conftest.py:63-70].
  The version-name helpers [src tests\test_pyenv_helpers.py:129-165] behave as follows:
  - `Native("3.8.9")` is `3.8.9` on AMD64 and `3.8.9-win32` on X86.
  - `Arch("3.8.9")` is always `3.8.9`.
  - `X86(v)` is `v-win32`.
- **Fake versions.** Each fake version contains the following files [src tests\test_pyenv_helpers.py:19-34, 75-95]:
  - in the version root: `python.exe`, `pythonw.exe`, `python3.exe`, `python38.exe`, `python3.8.exe`, the matching
    `pythonw*.exe`, and `version.bat`;
  - in `Scripts`: `pip.exe`, `pip3.exe`, `pip3.8.exe`, `easy_install.exe`, `easy_install-3.8.exe`, `hello.bat` and
    `version.bat`.
- **Version files.** Global and local files are written with Python `print()` in text mode, so they have CRLF endings
  and one version per line [src tests\test_pyenv_helpers.py:50-53, 96-101].

## Conventions shared by all commands

- **Stream.** Every message pyenv-win itself emits goes to **stdout**, including error messages. It uses batch `echo`
  or `WScript.Echo`, and no script writes to stderr on purpose [src: grep of `pyenv-win\bin` and `pyenv-win\libexec`
  for `StdErr`, `>&2` and `1>&2` finds none]. stderr carries only three things: cmd.exe's own diagnostics,
  `where.exe` diagnostics, and VBScript runtime errors.
- **Line endings.** Every output line ends in CRLF. `WScript.Echo` appends `\r\n` [test
  tests\test_pyenv_feature_version.py:64-71], and batch `echo` appends `\r\n` [probe].
- **Extra CRLF on relayed output.** In some places pyenv.vbs runs a child process and prints the child's captured
  stdout with `WScript.Echo`: `PrintHelp`, `PrintVersion`, `shims`, and `which`'s suggestion list. `WScript.Echo` then
  adds one CRLF after the child's own final CRLF, which leaves a trailing empty line
  [src pyenv-win\libexec\pyenv.vbs:47-67, 81, 165].
- **Exit codes.** pyenv.bat passes on the exit code of `cscript` or of the plugin:
  `|| goto :error` leads to `exit /b %errorlevel%` [src pyenv-win\bin\pyenv.bat:9, 57, 168, 219-220]. Success paths
  use a bare `exit /b` or `EXIT /B`, which leaves `%errorlevel%` unchanged. That value is normally 0, but this is
  UNCONFIRMED where it is only inherited, as noted per command.
- **VBScript runtime errors.** An example is `DeleteFile` on a missing file. The script aborts and prints this line to
  **stderr**:

  ```
  <full path of the .vbs>(<line>, <col>) Microsoft VBScript runtime error: <description>
  ```

  cscript then exits with **0**, and cmd sees errorlevel 0 [probe: own `.vbs` calling `DeleteFile` on a missing file;
  the output was `…rterr.vbs(5, 13) Microsoft VBScript runtime error: File not found` and errorlevel 0]. For
  non-English Windows the description text is UNCONFIRMED.
- **Encoding.**
  - Every pyenv.bat run switches the console to code page 65001 (`chcp 65001 >nul 2>&1`) and never restores it
    [src pyenv-win\bin\pyenv.bat:3].
  - Version files and shims are read and written as ANSI: `OpenTextFile` and `CreateTextFile` are called without the
    Unicode flag [src pyenv-win\libexec\libs\pyenv-lib.vbs:71, 108, 332, 340, 357, 364;
    pyenv-win\libexec\pyenv.vbs:356-358, 398-400].
  - How cscript encodes non-ASCII output: UNCONFIRMED.
- **Case.** pyenv.bat matches command names case-insensitively (`if /i`) [src pyenv-win\bin\pyenv.bat:53, 63], but
  pyenv.vbs's `Select Case arg(0)` is case-sensitive [src pyenv-win\libexec\pyenv.vbs:513-530]. As a result,
  `pyenv VERSION` reaches pyenv.vbs, matches no `Case`, prints nothing, and exits 0 [src]. Plugin lookup
  (`libexec\pyenv-<name>.*`) inherits the file system's case-insensitivity.

## Dispatch (`pyenv.bat`, `pyenv.ps1`, `bin\pyenv`)

### pyenv.bat routing order [src pyenv-win\bin\pyenv.bat]

| Step | Condition | Action | Lines |
|---|---|---|---|
| 0 | always | `@echo off`, `setlocal`, `chcp 65001 >nul 2>&1` | 1-3 |
| 1 | no arguments | `cscript //nologo "<bin>\..\libexec\pyenv.vbs"` runs `ShowHelp` (see `help`); then `exit /b` | 5, 8-11 |
| 2 | always | count the lines printed by `cmd /c echo skip`. The count minus one is the number of AutoRun lines, and it becomes `skip=N` in every later `for /f` capture | 13-16, 215-217 |
| 3 | `%1%2` equals `version` (case-insensitive) | `call :check_path` (see `version`) | 18, 184-207 |
| 4 | always | run `pyenv.vbs vname` **twice** to compute `bindir` and `extrapaths` (see `exec`) | 21-36 |
| 5 | `%2` is `--help` | `goto :plugin` with the full argument list, which runs `libexec\pyenv-%1.* --help …` | 39 |
| 6 | `%1` is `--help` | `call :plugin %2 %1`, then `exit /b` | 40-43 |
| 7 | `%1` is `help` | without `%2`: `call :plugin help --help`. With `%2`: `call :plugin %2 --help`; arguments after `%2` are dropped | 44-48 |
| 8 | `%1` is one of `rehash global local version vname version-name versions commands shims which whence help --help` | `cscript //nologo pyenv.vbs %*` | 51-60 |
| 9 | `%1` is `exec` | `:exec` | 63-83 |
| 10 | anything else | `:plugin` | 63, 131-169 |

- Step 4 runs on **every** invocation that has arguments, including `help`, `--version`, `shell` and unknown commands.
  `vname` creates `<pyenv-win>\versions` when it is missing [src pyenv-win\libexec\pyenv.vbs:457], so any such
  invocation creates that folder. `vname`'s output (including its error text) is consumed by `for /f` and never
  shown [src pyenv.bat:23, 26].
- The entries `help` and `--help` in step 8 are unreachable, because steps 6 and 7 handle those arguments first.

`:plugin` [src pyenv-win\bin\pyenv.bat:131-169]:

- **Lookup.** It tries `<bin>\..\libexec\pyenv-<%1>` with `.bat`, `.cmd`, `.vbs` and `.lnk`, in that order.
  - `.bat` and `.cmd` run as `call "<file>" <rest>`.
  - `.vbs` runs as `cscript //nologo "<file>" <rest>`.
  - `.lnk` runs `start '' "<exe>.bat"` [src :136-146].
- **Arguments.** `<rest>` is the original argument string with the first argument and the one character after it
  removed [src :153-164].
- **No match.** If none of the files exists, it prints this on stdout and exits 1 [src :147-149]:

  ```
  pyenv: no such command '<%1>'
  ```

  `<%1>` is echoed exactly as typed, quotes included.
- **Environment.** Before running the plugin, `endlocal && endlocal` ends pyenv.bat's `setlocal`, so variables the
  plugin sets reach the caller. Only `pyenv-shell.bat` sets any [src :165-168].

Consequences for the M1 commands [src]:

- `pyenv --help` on its own: step 6 runs `call :plugin  --help` with an empty `%2`, so inside `:plugin` `%1` is
  `--help`. No `libexec\pyenv---help.*` exists, so the output is `pyenv: no such command '--help'` with exit 1
  [src pyenv.bat:40-43, 147-149; not executed].
- `pyenv --version` runs the plugin `pyenv---version.bat`, because `--version` is not in the step-8 list
  [src :51, 63].
- `pyenv shell …` and `pyenv latest …` run the plugins `pyenv-shell.bat` and `pyenv-latest.vbs`.
- `root`, `prefix`, `version-origin` and `version-file` have no plugin file. Each prints
  `pyenv: no such command '<name>'` and exits 1.

### pyenv.ps1 [src pyenv-win\bin\pyenv.ps1]

- Line 1 sets `$OutputEncoding`, `[console]::InputEncoding` and `[console]::OutputEncoding` to UTF-8.
- Lines 3-18 apply when `$Args.Count -ge 2` and `$Args[0] -eq "shell"`. PowerShell's `-eq` is case-insensitive.
  - `--help`: run `pyenv.bat @Args` and exit with its code.
  - `--unset`: remove `Env:PYENV_VERSION` if it exists.
  - Anything else: run `cscript //nologo "$PSScriptRoot\..\libexec\pyenv.vbs" @Args` directly. pyenv.bat is **not**
    run, so neither the `chcp` nor the `vname` preamble happens.
    - On a non-zero exit, the captured lines are printed joined with `[Environment]::NewLine`, and the script exits
      with that code.
    - Otherwise `$Env:PYENV_VERSION` is set to the captured output.
- Every other invocation runs `pyenv.bat @Args` and then `Exit $LastExitCode` (lines 19-22).

### bin\pyenv, the sh wrapper [src pyenv-win\bin\pyenv:3]

The wrapper runs:

```
MSYS2_ARG_CONV_EXCL="/C" exec cmd /C call "$(cygpath -wa "$(dirname "$0")")/pyenv.bat" "$@"
```

Its output and exit code are pyenv.bat's.

## Version selection (shared by version, version-name, vname, which, exec, versions)

### Precedence [src pyenv-win\libexec\libs\pyenv-lib.vbs:208-236]

1. `PYENV_VERSION`, if it is non-empty.
2. Otherwise the nearest `.python-version` (see the search rules below).
3. Otherwise the global file.

The sources are **not merged**: the first non-empty source supplies every selected version.

`GetCurrentVersionsNoError` returns an ordered Dictionary that maps each name to its origin:

- **From `PYENV_VERSION`.**
  - The value is split with `Split(value)`, VBScript's default single-space delimiter; tabs do not separate names
    [src :146].
  - Consecutive, leading or trailing spaces produce empty names: `Split("a  b")` has 3 elements [probe].
  - The names are **not** prefix-resolved [src :217].
  - The origin is the literal text `%PYENV_VERSION%` [src :148].
- **Empty `PYENV_VERSION`.** A variable that is defined but empty (`""`) counts as unset
  [src :145; test tests\test_pyenv_feature_shell.py:31-33].
- **From the local or global file.** Each name goes through `TryResolveVersion(name, False)`, which is prefix
  resolution against the installed versions [src :223, 231]. The origin is the full path of the file that was read.
- **Duplicates.** Names that resolve to the same value collapse into one entry, at the first position
  (`versions.Item(k) = v`) [src :217, 223, 231].

`GetCurrentVersions` is the same, except that an empty result prints the following on stdout and exits 1
[src pyenv-lib.vbs:193-206; test tests\test_pyenv_feature_version.py:22-33]:

```
No global/local python version has been set yet. Please set the global/local version by typing:
pyenv global <python-version>
pyenv global 3.7.4
pyenv local <python-version>
pyenv local 3.7.4
```

(`GetCurrentVersion`, singular, at pyenv-lib.vbs:169-182, has a different message with `pyenv global` twice. Nothing
calls it [src: grep].)

### How `.python-version` is found [src pyenv-win\libexec\libs\pyenv-lib.vbs:99-126]

- **Search path.** The search starts at the current directory and checks `<dir>\.python-version`. It then moves to each
  parent with `GetParentFolderName`, up to and including the drive root, and stops when the parent is `""`
  [probe: `GetParentFolderName("C:\a")` is `C:\` and `GetParentFolderName("C:\")` is `""`].
- **Drive root.** At the drive root the checked path is `C:\` + `\.python-version`, which is `C:\\.python-version`
  with a doubled backslash. FSO `FileExists` accepts doubled backslashes [probe], and the doubled string is what gets
  printed as the origin [src :106, 113].
- **The first existing file ends the search, even if it contains no version lines.** The local result is then Null,
  and selection falls through to the global file [src :107-125]. The test fixture relies on this with its empty
  `.python-version` above the cwd [src tests\conftest.py:83].

### Where the global version file lives [src pyenv-win\libexec\libs\pyenv-lib.vbs:63-86]

The global file is `<pyenv-win>\version`, for example `C:\Users\JM\.pyenv\pyenv-win\version`. It is parsed the same
way as `.python-version`. This installation's global file contains `3.14.2\r\n` [disk].

### Version file format (both files) [src pyenv-lib.vbs:71-78, 108-115]

Each file is opened with `OpenTextFile(fname)` (ForReading, ANSI) and read with `ReadLine` until `AtEndOfStream`. A
line is kept unless it is exactly `""`. The table shows what a probe that copies this loop got for each input.

| File bytes | Versions produced | Evidence |
|---|---|---|
| `3.9.1\r\n3.8.2\r\n` | `3.9.1`, `3.8.2` | probe; the tests also use CRLF files |
| `3.9.1\n3.8.2\n` (LF) | `3.9.1`, `3.8.2` | probe |
| `3.9.1\r3.8.2\r` (CR only) | one name, `3.9.1\r3.8.2\r`: a lone CR does not end a line | probe |
| `3.9.1` (no final newline) | `3.9.1` | probe |
| `\r\n\r\n` (blank lines only) | none, and the file still stops the search | probe + src |
| `  3.9.1  ` | `  3.9.1  `: whitespace is **not trimmed** | probe |
| `# comment` | `# comment`: there is **no comment syntax** | probe |
| `\t3.8` | `\t3.8` | probe |
| UTF-8 BOM, then `3.9.1` | `ï»¿3.9.1`: the BOM bytes 239 187 191 are kept | probe |
| UTF-16LE (BOM `FF FE`) | garbage names (`ÿþ3\0.\09\0\r\0` and `\0`) | probe |
| `3.8 3.9` on one line | a single name, `3.8 3.9`. Only `PYENV_VERSION` is split on spaces. | src |

- A whitespace-only line, such as a single space, is a version, because only `""` is skipped [src :74, 111].
- Names with surrounding whitespace, `#` or spaces fail `IsVersion` (`^[a-zA-Z_0-9-.]+$`). `GetBinDir` therefore
  rejects them for `local`, `global` and `shell` [src pyenv-lib.vbs:253-259, 265]. How such names behave in
  `FolderExists` (for `which`) and for `exec`: UNCONFIRMED.

### Prefix resolution: `TryResolveVersion` and `FindLatestVersion` [src pyenv-win\libexec\libs\pyenv-install-lib.vbs:447-516]

- **Candidates.**
  - Installed: the names of the subfolders of `versions`, in FSO enumeration order
    [src :466; pyenv-lib.vbs:238-251].
  - Known (`latest -k`): the `<code>` values in `.versions_cache.xml` [src :450-464].
- **Architecture suffix.** `GetArchPostfix()` maps `AMD64` to `""`, `X86` to `-win32` and `ARM64` to `-arm64`.
  Anything else yields Empty, which behaves as `""` [src pyenv-lib.vbs:429-438].
- **Which candidates qualify.** A candidate qualifies only if **all** of these hold [src :479-487]:
  1. `Left(candidate, Len(prefix)) = prefix`. The comparison is case-sensitive.
  2. Either `candidate = prefix & arch`, or the character right after the prefix is `.`.
  3. It fully matches `^(\d+)(?:\.(\d+))?(?:\.(\d+))?(?:([a-z]+)(\d*))?([\.-](?:amd64|arm64|win32))?$`, ignoring case
     [src :61-65].
  4. The pre-release group `([a-z]+)` is empty, so no `a`, `b`, `rc`, `dev`, `t` and so on.
  5. The architecture group is exactly equal to the arch suffix. The comparison is case-sensitive: `-WIN32` is not
     `-win32`. On AMD64 a `-amd64` suffix disqualifies the candidate.
- **How "newest" is decided.** The winner is the maximum under `SymanticCompare`
  [src :314-339]:
  - Compare major, then minor, then patch, each as a number (`CLng`).
  - A missing component counts as 0.
  - Ties have a hazard. The first-enumerated candidate is kept until the comparison reaches the ARM field, and there
    `SymanticCompare` reads `SubMatches(6)`, but the regex has only 6 groups (indices 0-5). So two qualifying
    candidates that are equal in major, minor and patch raise a VBScript runtime error,
    `Invalid procedure call or argument` [src :363-373; probe: `SubMatches(6)` on a 6-group match raises exactly that
    error, and cscript exits 0]. Examples: `3.9` and `3.9.0` both installed, or `3.10.1` and `3.10.01`. The full
    pyenv code path was not executed.
- **Result.** The result is `JoinVersionString(best)`, which rebuilds
  `major[.minor][.patch][pre][prenum][arch]` from the captured text [src :433-442, 504]. If nothing qualifies,
  `FindLatestVersion` returns `""` and `TryResolveVersion` returns its input unchanged [src :511-515].
- **Examples.**
  - Installed `3.1.4 3.11.0 3.2.0 3.2.5 3.9.1` [test tests\test_pyenv_feature_latest.py:15-28]:
    - `3.1` resolves to `3.1.4`, not `3.11.0`.
    - `3.2` resolves to `3.2.5`.
    - `3.2.5` resolves to `3.2.5`.
    - `1` resolves to nothing.
  - Installed `3.9.4 3.7.2 3.7.7 3.9.1` [test :49-54]: `3` resolves to `3.9.4` and `3.7` to `3.7.7`.
  - `pyenv local 3` with `3.7.7` and `3.8.9` installed: `vname` then prints `3.8.9`
    [test tests\test_pyenv_feature_local.py:24-35].
  - Installed `3.1.0-win32` and `3.1.4` [test tests\test_pyenv_feature_latest.py:31-38]: on X86, `3.1` resolves to
    `3.1.0-win32`; on AMD64 it resolves to `3.1.4`.
- **Edge cases derived from the code** [src]:
  - A prefix that ends in `.`, such as `3.`, never qualifies, because the character after it would have to be `.`.
  - An arch-suffixed prefix such as `3.1.0-win32` does not qualify against `3.1.0-win32`: that is neither
    `prefix & arch` nor followed by a `.`. It resolves to itself.
  - Names such as `pypy3.10-v7.3.17` never qualify, because they fail the regex.
  - ARM codes in the known-versions DB end in `-arm` (for example `3.11.0a5-arm`) [disk .versions_cache.xml], so they
    never match the expected `-arm64`.
- **Where resolution applies.** Resolution applies to local and global names, both during selection and in
  `local`/`global` validation, and to `latest`. It does **not** apply to `PYENV_VERSION`, or to the arguments of
  `pyenv shell <v>` [src pyenv-lib.vbs:217; pyenv.vbs:423-424].

## shims

- **Synopsis.** `pyenv shims`, or `pyenv shims --short` [src pyenv-win\libexec\pyenv-shims.bat:5-6].
- **Implementation.** `CommandShims` [src pyenv-win\libexec\pyenv.vbs:69-82]:
  - With no second argument it runs `cmd /c dir <shims>/s /b` [src :75]. There is no space before `/s`, and the path
    is unquoted. The result is dir's stdout followed by one extra CRLF. dir prints one absolute path per line,

  system files are excluded (dir defaults).
- **UNCONFIRMED.**
  - A pyenv path that contains spaces (unquoted) splits into several `dir` arguments. The resulting output is
    UNCONFIRMED.
  - Output for non-ASCII file names.
  - Leakage of cmd AutoRun output, since `cmd /c` runs without `/d`.

- **Logic** [src pyenv-win\libexec\pyenv---version.bat]:
  1. Line 3 sets `KNOWN_VER` to the first whitespace-delimited token of the last non-empty line of
     `<libexec>\..\..\.version`, using `for /f` over `type` [probe: for a multi-line CRLF file the variable ends up
     holding the last line's token]. Here it is `3.1.1`.
  2. If `PYENV` is empty or undefined (lines 19-27), the script prints
     `PYENV variable is not set, recommended to set the variable.`. It then prints
     `PYENV_ROOT variable is not set, recommended to set the variable.` if `PYENV_ROOT` is empty, and
     `PYENV_HOME variable is not set, recommended to set the variable.` if `PYENV_HOME` is empty. The version is

  4. Otherwise the version is `KNOWN_VER` (lines 31-32).
  5. Line 34 runs `echo pyenv %version%`.

- **Implementation.** `CommandWhence` [src pyenv-win\libexec\pyenv.vbs:171-261]. It **ignores version selection** and
  scans every installed version in FSO enumeration order.
- **Arguments.**
  - No argument, or an empty one, runs `PrintHelp`: help text plus an extra CRLF, exit **1**.
  - `--path` (exact) with no program also runs `PrintHelp` with exit 1 [src :173-196].

- **Search** in each version folder `D` [src :202-257]:
  1. `D\<p>`. On a hit it prints, and sets `found`.
  2. If nothing has been found yet, or `--path` is given: the first extension `e` for which `D\<p><e>` exists (stop at
     the first). On a hit it prints, and sets `found`.

    set `found`.

- **Examples** [test :21-39]:

## exec

- **Synopsis.** `pyenv exec <command> [arg1 arg2...]` [src pyenv-win\libexec\pyenv-exec.bat:5]. There are no flags.
  `pyenv exec --help`, `pyenv help exec` and `pyenv --help exec` print help
  [test tests\test_pyenv_feature_exec.py:96-111].
- **Implementation.** Entirely inside pyenv.bat [src pyenv-win\bin\pyenv.bat:21-36, 65-129, 178-181]. pyenv.vbs is
  used only through the two `vname` captures.

### Steps

1. **Collect versions and `bindir`.** Every line of `pyenv.vbs vname` (resolved selected names, in order) goes through
   `:extrapath`. It sets `bindir` to the `%~dpf` normalization of `<bin>\..\versions\<name>` and appends
   `<bindir>;<bindir>\Scripts;<bindir>\bin;` to `extrapaths` [src :23, 178-181].
2. **User-site `Scripts`.** For each `vname` line split at the first `-` into `A` and `B`, it builds
   `%APPDATA%\Python\Python<x><y>-32\Scripts;` if `B` is `win32` (case-insensitive), or
   `%APPDATA%\Python\Python<x><y>\Scripts;` otherwise. `x` and `y` are the first two `.`-separated fields of `A`
   [src :26-36]. The `set` happens inside the `for` body with `%extrapaths%` expanded when the loop is parsed, so
   **only the last version's entry survives** [probe: an identical loop appending `a`, `b`, `c` ended with only `c`
   appended].
3. **Version check.** `if not exist "%bindir%"` tests **only the last selected version** [src :67-72]. When it fails,
   the command prints the following on stdout and exits 1:

   ```
   No global/local python version has been set yet. Please set the global/local version by typing:
   pyenv global 3.7.4
   pyenv local 3.7.4
   ```

   This 3-line message is pyenv-win's own exec wording, and it differs from the 5-line pyenv.vbs message.
   - It is printed both when nothing is selected and when the last selected version is not installed. When nothing is
     selected, `vname`'s error lines become fake version names, and the last one, `pyenv local 3.7.4`, is not a
     folder.
   - The test asserts only the exit code, 1 [test :143-150].
   - If an earlier selected version is missing but the last one exists, exec proceeds, and the missing folders stay on
     PATH.
4. **Command line.** The command line is `%*` with its first 5 characters removed, that is `exec` and the one character
   after it [src :74-75]. Any further separators before the command are kept.
5. **Child PATH.** `:remove_shims_from_path` [src :85-129] sets PATH to `extrapaths` and then appends every entry of
   the original PATH. Empty entries are dropped and quotes are removed. Each entry is rewritten as `%~dpf`, which
   resolves `..`, keeps a trailing `\` and uses on-disk case [probe]. Each is followed by `;`. The one entry equal,
   case-insensitively, to the normalized `<bin>\..\shims` is omitted. An entry spelled with a trailing backslash does
   not match and is **not** removed [src :121; probe]. The result ends with `;`.
6. **Run and restore.** The command line runs as a plain command in pyenv.bat's cmd (`%cmdline% ||  goto :error`),
   and then `endlocal` restores the caller's PATH [src :80-83; test :114-124].

### Resulting child PATH

For selected versions `V1 … Vn`, where `P` is the normalized `<pyenv-win>`:

```
P\versions\V1;P\versions\V1\Scripts;P\versions\V1\bin;…;P\versions\Vn;P\versions\Vn\Scripts;P\versions\Vn\bin;%APPDATA%\Python\Python<XY of Vn>[-32]\Scripts;<original PATH entries without the shims dir, normalized>;
```

The prefix up to `Vn\bin;` is confirmed by the test for a local file of `3.7.7` and `3.8.9`, which starts
`{pyenv}\versions\3.7.7;{pyenv}\versions\3.7.7\Scripts;{pyenv}\versions\3.7.7\bin;{pyenv}\versions\3.8.9;…\3.8.9\bin;`
[test :127-140].

### How the executable is found

- There is no pyenv-level lookup. cmd.exe resolves the first word of the command line with its normal search:
  - built-in commands first (`echo`, `set`, `dir`, …);
  - then the current directory;
  - then each PATH entry in order, trying the `PATHEXT` extensions in order.

  This is documented cmd.exe behavior and was not probed. Consequences:
  - A `python.exe` in the cwd wins over the selected version.
  - Within one version, the version root beats `Scripts`, which beats `bin`.
  - The first version beats later versions.
  - The shims are skipped, so a program that only another version provides is not found
    [test :157-164, where `python310` is not recognized].
- `.bat` and `.cmd` targets run without `call`, so control does not return to pyenv.bat. `hello.bat` in `Scripts`
  works [test :153-154].

### Exit codes and errors

- **Child's exit code.** A non-zero child exit code is propagated through `|| goto :error` and
  `exit /b %errorlevel%`, and a zero exit code gives 0 [probe: an identical construct running `cmd /c exit 7`
  returned 7].
- **Command not found.** cmd prints the following on **stderr** [test :157-164]:

  ```
  '<command>' is not recognized as an internal or external command,
  operable program or batch file.
  ```

  The exit code is **1**, not 9009: under `||`, cmd sets errorlevel 1 for a command it cannot find
  [probe: `x || goto :error`, then `exit /b %errorlevel%`, returned 1, while a bare `x` gave 9009].
- **`pyenv exec` with no command** (when the version check passes). The command line becomes empty, so the line
  reduces to ` ||  goto :error`, a cmd syntax error. stderr receives `|| was unexpected at this time.` and the exit code
  is **255** [probe of the identical lines].
- **Argument pass-through.** Arguments reach the child with their quoting intact for spaces, single quotes, double
  quotes, `!`, `#` and unbalanced quotes, both through `pyenv exec` and through the `python.bat` shim [test :45-93].
  The test's outer `cmd /d /c call …` already expands `%World%`, so the test does not show whether pyenv.bat itself
  expands `%` a second time: UNCONFIRMED. Carets and `%` behavior through the shim's `call`: UNCONFIRMED.

### How the batch shims reach exec, and the `chcp` line

- **Shim body.** A `.bat` shim contains `@echo off`, `chcp 1250 > NUL` and `call pyenv exec %~n0 %*`
  [src pyenv-lib.vbs:332-344].
  - cmd resolves `pyenv` through PATH and PATHEXT, normally to `<pyenv-win>\bin\pyenv.bat`.
  - `%~n0` is the shim's own base name, so `python3.8.bat` runs `pyenv exec python3.8 …`.
  - Because exec removes the shims folder from PATH, the name then resolves to the selected version's real file.
- **Exit codes through the shim** [probe: shims with the identical bodies and a fake `pyenv.bat` that exits 7 for
  `exec`]:
  - A non-`pip*` shim returns the child's exit code (7).
  - A `pip*` shim (with the extra `call pyenv rehash`) returns **`pyenv rehash`'s exit code (0)**, so pip's failure is
    lost.
- **`chcp 1250`.**
  - The code page 1250 is a **hard-coded literal** in the shim template [src pyenv-lib.vbs:334, 342]. It is not taken
    from the system or the user.
  - Its stated purpose, from changelog 2.64.3, is: "Shims now use cp1250 as the default code page since Python2 will
    never actually support cp65001 … cp1250 has better support for upper ANSI characters" [src docs\changelog.md:105;
    git 385026e, 2020-03-14, "Py2 doesn't support cp65001, change to 1250 for proper ANSI output."].
  - The pyenv.bat that the shim calls then runs `chcp 65001` as its third line [src pyenv.bat:3; git f27c33b,
    2023-12-27, "Set active codepage to UTF-8"]. So the child program runs under code page **65001**, the shim's 1250
    is overridden before any program starts, and the console stays at 65001 after the shim returns.
- **sh shims** run `pyenv exec $(basename "$0") "$@"`, which reaches pyenv.bat through `bin\pyenv`. They are written
  with CRLF line endings (see `rehash`). Whether a `\r` then reaches the last argument under Git Bash or MSYS is
  UNCONFIRMED.

## rehash

- **Synopsis.** `pyenv rehash`. There are no flags. `--help` prints help through pyenv.bat. pyenv.vbs also handles
  `rehash --help` with `PrintHelp` and exit 0, but pyenv.bat never lets that path run [src pyenv.vbs:312-314].
- **Implementation.** `CommandRehash` [src pyenv-win\libexec\pyenv.vbs:310-323], then `Rehash`
  [src pyenv-win\libexec\libs\pyenv-lib.vbs:375-427].
- **No versions.** If `versions` has no subfolders, or does not exist, the command prints the following on stdout,
  **exit 0**, and leaves the shims untouched [src :317-319; test tests\test_pyenv_feature_rehash.py:17-21]:

  ```
  No version installed. Please install one with 'pyenv install <version>'.
  ```

- **Otherwise** it prints nothing and exits 0 [test :24-52].

### Algorithm [src pyenv-lib.vbs:375-427]

1. Create `shims` if it is missing, then **delete every file directly inside `shims`**, including files pyenv-win did
   not create. Subfolders are untouched.
2. For each installed version, in FSO enumeration order, the scanned extension set is every `PATHEXT` entry
   lower-cased without its dot, plus `py` and `pyw` [src :392; :273-306]. Files with any other extension, or with no
   extension, are ignored. Base name = `GetBaseName`, the name up to the last dot, so `python3.8.exe` gives
   `python3.8`.
3. **Version root.** Each matching file gets a `.bat` shim and an extensionless sh shim for its base name. If its
   extension is not `exe`, it **also** gets a `.lnk` shim [src :394-407].
4. **`Scripts`, then `bin`**, when present [src :410-425]:
   - `exe` files get a `.bat` shim and an extensionless sh shim.
   - Other matching files (`.bat`, `.cmd`, `.py`, …) get **only** a `.lnk` shim, so no cmd-callable shim.
5. The scan is not recursive: only the root, `Scripts` and `bin` are scanned.
6. The current version selection is irrelevant; every installed version is shimmed [test :45-52].

### How duplicates across versions are handled

- Every writer skips a target that already exists [src :314, 330, 355], so the first creator in enumeration order wins.
  Within one version the order is root, then `Scripts`, then `bin`.
- `.bat` and sh contents do not depend on the version. A `.lnk` records its target, so it points to the first version
  enumerated that had a non-exe file with that base name. For example, `shims\aws.lnk` targets
  `…\versions\3.8.2\Scripts\aws.cmd` on this host [disk].

### The `pip` prefix rule

A base name that begins with `pip` gets an extra `rehash` line in both shim types. The test is
`InStr(1, baseName, "pip") = 1`, which is case-sensitive [src :331, 356; probe: `InStr(1, "Pip3", "pip")` = 0]. It
matches `pip`, `pip3`, `pip3.8`, `pipx`, `pipenv`, `pip-compile` and so on, but not `PIP`.

## latest

- **Synopsis.** `pyenv latest [-k|--known] [-q|--quiet] <prefix>` [src pyenv-win\libexec\pyenv-latest.vbs:21].
- **Route.** `:plugin` runs `cscript //nologo "<libexec>\pyenv-latest.vbs" <args>`, and the exit code is propagated
  [src pyenv.bat:142-143, 168].

### Argument parsing [src pyenv-latest.vbs:42-52]

- The arguments are scanned in order, and matching is case-sensitive:
  - `--help` prints the help text and exits 0 immediately, even after other arguments.
  - `-k` or `--known` selects the known-versions DB.
  - `-q` or `--quiet` suppresses messages.
  - **Any other argument becomes the prefix; the last one wins.** `-K` is therefore a prefix.
- With no arguments at all, the command prints the help text and exits **1** [src :54-58;
  test tests\test_pyenv_feature_latest.py:5-12].

### Output and errors

- **Result.** On success it prints the resolved version, then CRLF, and exits 0 [src :71-72]. Resolution is
  `FindLatestVersion`, described under *Prefix resolution* above. Examples are in the tests
  [test :15-54].
- **No prefix** (only flags). The following is printed unless quiet, and the exit code is 1 [src :60-66]:

  ```
  pyenv-latest: missing <prefix> argument
  ```

- **No match.** One of the following is printed unless quiet, and the exit code is 1 [src :74-82; test :22-25]:

  ```
  pyenv-latest: no installed versions match the prefix '<prefix>'.
  pyenv-latest: no known versions match the prefix '<prefix>'.
  ```

  Under `-q` nothing is printed, and the exit code is still 1 [test :41-46].
- **Known DB problems.**
  - With `-k`, a missing `.versions_cache.xml` yields no candidates, which is the "no known versions" message
    [src pyenv-install-lib.vbs:187].
  - A cache that fails schema validation prints the following and exits 1 [src :203-208]:

    ```
    Validation error in DB cache(0x<HEX>) on line <n>, pos <m>:
    <reason>
    ```

- **Filters.** Pre-releases are never returned, and only candidates with the current architecture suffix are
  returned. `3.1` does not match `3.10.x` or `3.11.x`.

## shell

The following applies to `pyenv shell` run from cmd through pyenv.bat. Its only effect beyond printing is setting
`PYENV_VERSION`.

- **Synopsis.** `pyenv shell`, `pyenv shell <version> [<version2> …]`, or `pyenv shell --unset`
  [src pyenv-win\libexec\pyenv-shell.bat:10-11].
- **Route.** `:plugin` runs `call "<libexec>\pyenv-shell.bat" <args>`, after `endlocal` twice so that the plugin can
  change the caller's environment [src pyenv.bat:163-168].
- **Help.** `--help`, only when it is the first argument to the plugin, prints the help text [src pyenv-shell.bat:9-18].

### No arguments [src pyenv-shell.bat:20-25]

- If `PYENV_VERSION` is empty or undefined, the command prints:

  ```
  no shell-specific version configured
  ```

  [test tests\test_pyenv_feature_shell.py:31-33]
- Otherwise it prints `%PYENV_VERSION%` exactly as stored: raw, unresolved and unvalidated, with several versions
  space-separated [test :36-38, 99-101].
- Both outputs go to stdout. The exit code is not set explicitly; it is inherited (UNCONFIRMED, normally 0). A value
  containing cmd metacharacters (`&`, `|`, `<`, `>`) goes through the unquoted `echo`: UNCONFIRMED.

### `--unset` [src :27-28]

The flag is case-insensitive (`if /i`). The command runs `endlocal && set "PYENV_VERSION="`. It prints nothing and
removes the variable from the calling session.

### Set [src :30-35, 43-45; pyenv.vbs:409-430]

1. **Validation.** `cscript pyenv.vbs shell <args> 1> nul` runs first. `CommandShell` applies `Check32Bit` to each
   argument: on X86 it appends `-win32` unless the name already ends in `-win32`, case-insensitively
   [src pyenv-lib.vbs:450-455]. It then calls `GetBinDir` with **no prefix resolution** and **no `system` special
   case**. So `pyenv shell 3.8` fails unless a folder named exactly `3.8` exists [src pyenv.vbs:423-424].
2. **On failure.** `:error` runs the same cscript again, **unmuted**, so the *not-installed* message appears once on
   stdout, and the batch exits with cscript's code, 1 [test :56-58, 94-96]. For example, on X86
   `pyenv shell 3.7.7 3.8.9` with only `3.7.7-win32` installed prints the message for `3.8.9-win32`.
3. **On success.** cscript prints the names joined with single spaces. `for /f` captures that line and runs
   `endlocal && set "PYENV_VERSION=<line>"`. **Nothing is printed.** On X86 each value carries `-win32` [test :41-53,
   80-91].

Other details:

- `GetBinDir` validates the names in order and stops at the first failure.
- The global and local files are unaffected [test :61-77].
- In pyenv.vbs, `shell` with no arguments prints `Not enough parameters passed to pyenv.vbs shell`, and
  `shell --unset` is a no-op [src pyenv.vbs:412-416]. pyenv.bat never lets either path run.

### PowerShell (`pyenv.ps1`)

The PowerShell wrapper behaves the same, with these differences [src pyenv-win\bin\pyenv.ps1:3-18]:

- With two or more arguments, it calls pyenv.vbs directly, without running pyenv.bat.
- On failure it prints the captured lines joined with `[Environment]::NewLine`, then exits with cscript's code.
- On success it sets `$Env:PYENV_VERSION` to the captured output and prints nothing.
- `shell --unset` removes the variable.
- `pyenv shell` with no arguments falls through to `pyenv.bat shell`, so the printing described above applies.
